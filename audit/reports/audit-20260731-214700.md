## Critical

## High

### H-01 — CSV export and report queries are unbounded by date-range size

- **Affected:** `backend/src/api/v1/reports/report.service.ts` (`salesSummary`, `topProducts`, `ordersExportCsv`, `paymentMethods`)
- **Why it matters:** Any authenticated shop owner can request a multi-year range; service loads all matching orders/line items/payments into memory and builds CSV in one string.
- **Likely impact:** Memory spikes, slow responses, potential DoS for shops with large histories; CSV response timeouts.
- **Mitigation:** Cap range (e.g. 366 days), paginate/stream CSV, or use SQL aggregation instead of full `findMany` + in-memory reduce.

### H-02 — Web refresh tokens still in `localStorage` (carry-over)

- **Affected:** `frontend/src/features/auth/token-storage.ts`, `frontend/src/features/reports/api.ts` (CSV uses raw `fetch` + token)
- **Why it matters:** XSS can steal refresh tokens; CSV path does not use coordinated refresh in `api-client.ts`.
- **Likely impact:** Session takeover; failed export on expired access token without retry.
- **Mitigation:** HttpOnly cookie refresh; shared download helper with 401 refresh retry.

## Medium

### M-01 — CSV export includes cancelled orders; revenue reports exclude them

- **Affected:** `report.service.ts` — `ACTIVE_ORDER_WHERE` on summaries but not on `ordersExportCsv`
- **Why it matters:** Inconsistent semantics; staff may double-count or misread exports vs dashboard revenue.
- **Likely impact:** Spreadsheet analysis diverges from on-screen totals.
- **Mitigation:** Align export filter with spec intent (document or exclude `CANCELLED` by default).

### M-02 — Pre-order pipeline includes `COMPLETED` pre-orders

- **Affected:** `preorderPipeline()` — filters `status: { not: 'CANCELLED' }` only
- **Why it matters:** RPT-03 describes a “pipeline”; completed orders are not actionable pipeline work.
- **Likely impact:** Cluttered pipeline table; inflated counts vs staff mental model.
- **Mitigation:** Exclude `COMPLETED` (and optionally `CANCELLED`) or split “open pipeline” vs “historical by status”.

### M-03 — No PostgreSQL production path (carry-over)

- **Affected:** `backend/prisma/`, deployment config
- **Why it matters:** Spec targets PostgreSQL for production; SQLite-only today.
- **Likely impact:** Cannot scale past pilot; report aggregations worsen under concurrency.
- **Mitigation:** Add PostgreSQL schema/migrations before Milestone 6 pilot.

### M-04 — Report date parsing is timezone-sensitive

- **Affected:** `resolveDateRange()` — `new Date(\`${date}T00:00:00.000\`)` without explicit UTC
- **Why it matters:** Range boundaries shift in non-UTC locales; edge orders may fall in/out of reports.
- **Likely impact:** Off-by-one-day revenue for shops near timezone boundaries.
- **Mitigation:** Use UTC consistently or shop timezone from settings.

### M-05 — No frontend tests for `/reports`

- **Affected:** `frontend/src/features/reports/*`
- **Why it matters:** Date filter wiring and CSV download are untested; regressions likely silent.
- **Likely impact:** Broken export or empty UI after refactors.
- **Mitigation:** Add Vitest tests for API param building and page render with mocked queries.

## Low

- **Affected:** `periodKey()` with `getDay()`
- **Likely impact:** Week labels differ from calendar expectations in some locales.
- **Mitigation:** Document or switch to ISO week.

### L-02 — `/dashboard` still placeholder while spec §9.2 lists today’s sales

- **Affected:** `frontend/src/pages/dashboard-page.tsx`
- **Likely impact:** Staff land on empty dashboard; reports live on separate route only.

### L-03 — Reports nav missing from mobile bottom bar

- **Mitigation:** Add to bottom nav or dashboard link.
